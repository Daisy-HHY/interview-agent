# 0.2.3 Runtime 诊断记录边界决策

**决策状态：** `keep-in-memory`  
**适用版本：** 0.2.3  
**目的：** 在没有完成隐私和存储评审前，不把 runtime 时间线扩展成默认持久化 trace。

## 1. 本版本决定

0.2.3 继续使用 Webview 内存时间线，不新增 runtime trace 文件、数据库、远程观测服务或跨会话查询。

内存时间线只服务当前调试会话；清空会话、重新初始化、扩展重载或进程结束后不保证保留。业务会话历史仍按原有 `.sessions/{id}.json` 规则保存，runtime 诊断事件不写入业务历史。

## 2. 允许字段

允许进入 `agent_event` 或当前内存时间线的字段：

- `schema_version`、`event`、`event_seq`、`elapsed_ms`、`step`；
- 工具名称 `tool`，不包含工具参数值和文件路径；
- `state`、`is_error`、`error_kind`；
- `delta_chars`、`result_chars`；
- 压缩前后消息数/token 数和压缩耗时等聚合数值；
- 预算软上限、硬上限、已用步数、命中状态和停止原因。

## 3. 禁止字段

禁止写入 runtime 诊断记录或普通日志：

- API Key、Authorization、Cookie 和其他凭据；
- 完整 system prompt、用户问题、模型回答和模型思考正文；
- 工具参数值、文件路径、工具结果正文和异常正文中的敏感内容；
- LLM summarizer 的完整摘要正文；
- 可以通过拼接恢复业务正文的高频原始 delta。

工具参数只允许在既有 `tool_call` UI 流程中按原有权限使用；它不属于本版本的 runtime 时间线或未来 trace 白名单。

## 4. 容量上限

当前最小时间线使用以下硬上限：

- 最多保留 80 条 runtime 事件；
- 单个工具名、状态和错误分类字段最多展示 160 个字符；
- 单行展示最多 320 个字符；
- 时间线展示总长度最多 12,000 个字符；
- 超限后丢弃最旧事件或截断字段，并显示计数；最终事件仍优先保留。

这些限制用于防止长任务、高频流式事件和异常长错误占满 Webview 内存或 DOM。

## 5. 后续持久化前必须补充的决策

只有同时明确以下事项，才可以进入 `session-diagnostic` 或 `trace-storage` 实现：

1. 用户是否显式开启，默认是否关闭；
2. 字段白名单、脱敏规则和访问权限；
3. 单会话上限、全局存储上限和文件格式版本；
4. 保留周期和自动清理时机；
5. 用户主动导出、删除和故障恢复行为；
6. 是否允许把诊断记录与业务 session 分离存储；
7. 旧版本和未来字段变更的迁移策略。

在这些问题没有评审结论前，0.2.3 保持 `keep-in-memory`，不为了实现“可查询”而默认落盘。
