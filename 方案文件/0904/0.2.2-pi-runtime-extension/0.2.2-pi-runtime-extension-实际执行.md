## 6. 验收步骤

1. 执行 Python 全量测试和 ruff，确认 `267 passed, 1 skipped` 与 `All checks passed!`。
2. 在 `vscode-extension` 执行 `npm test`、`npx tsc -p ./ --noEmit` 和 `npm run compile`，确认测试、类型检查和编译均通过。
3. 在无 `INTERVIEW_API_KEY`、无网络依赖条件下运行 FakeLLM `runtime=all`，确认 native/pi 完成，Pi 输出 `runtime=pi`、`status=done`、`required_tool_used=true`。
4. 在 VS Code 设置中开启 `interview.demoMode`，选择 `interview.agentRuntime=pi`，先关闭 `interview.compactionEnabled` 完成一轮，再开启压缩并降低 `interview.compactionTriggerTokens` 触发 checkpoint；确认 UI 诊断区显示压缩状态和事件时间线。
5. 检查时间线：文本回答和工具调用都应显示有序事件；连续流式事件被聚合，时间线不超过最大条数，不显示完整 prompt、参数值或工具结果。
6. 未配置 hook 文件时确认没有外部 Python 文件加载；对 workspace 外路径、符号链接、非 `.py`、目录、缺失文件和抛错文件执行安全评估，确认被拒绝或保持禁用。
7. 运行 fake MCP adapter 隔离测试，确认工具发现、注册、调用、重复名称和结果限制不需要网络，且未启用 MCP 时本地工具行为不变。
8. 使用旧 `.sessions/{id}.json` 恢复并继续对话，确认 system prompt、消息顺序和保存格式兼容。
9. 在 Pi Demo 中执行连续工具调用，确认输出间只保留一个可折叠轨迹组，完成后仍可展开查看每个工具调用。
10. 使用超过 8 个工具回合的 FakeLLM 场景确认 Pi 不提前停止；修改 `interview.piMaxSteps` 后确认达到安全阀会明确结束。

## 7. 验收标准

- checkpoint 压缩默认关闭，只影响本次模型请求上下文；失败、取消和非法结果可以回退，不隐式修改历史文件。
- system prompt、当前任务和合法 tool call/tool result 关系得到保留或安全处理，不制造孤立工具消息。
- Webview 事件时间线有序、限量、脱敏，且不改变 `stream/tool_call/done/error` 时序。
- `piHooksFile` 不会被隐式加载；0.2.2 的安全决策为默认不执行外部 Python hook 文件。
- FakeLLM CI 不依赖 API Key 和网络，能检查实际 runtime、工具顺序、必需工具、结束状态和敏感信息边界。
- MCP 仅提供接口合同和隔离测试，不产生默认远程工具执行路径。
- Webview 运行轨迹按输出间分组、可折叠、完成后保留，且不泄漏敏感正文。
- Pi runtime 无工具调用时自然结束，默认 32 回合仅作为可配置安全阀；native 默认行为不变。
- 0.2.1 既有功能和历史 JSON 兼容，默认 runtime 仍为 `native`。
- Python 测试、ruff、扩展测试、TypeScript 检查、compile 和 FakeLLM benchmark 全部通过。

## 8. 未覆盖风险

- FakeLLM 只能验证确定性行为和协议闭环，不能替代真实模型的摘要质量、工具选择质量、延迟和 token 成本评估。
- checkpoint 当前采用确定性最近消息保留策略，不是依赖额外模型生成的高质量语义摘要；真实 summarizer 留到后续版本评估。
- 外部 hook 文件本版本不执行；未来若开放，仍需进一步评审权限、凭据、导入隔离和 API 版本演进。
- MCP 尚未连接真实 provider，网络传输、鉴权、远程权限和审计仍未验证。
- 32 回合仍是防无限工具循环的硬安全阀；真实项目的最佳预算需要结合模型、工具耗时和上下文压力继续观测。
- CI workflow 已在仓库内完成配置和本地静态验证，实际云端 runner 结果需在推送后由 CI 平台确认。
