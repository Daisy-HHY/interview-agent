# Interview Agent 0.2.2 版本优化任务清单

## 1. 版本定位

**版本：** 0.2.2  
**主题：** Pi-style runtime 的上下文压缩、运行观测与扩展边界  
**当前阶段：** 已完成实施与回归验收；本文件同时作为 0.2.2 的验收基线。  
**版本目标：** 基于 0.2.1 已稳定的 runtime、context pipeline、`agent_event` 和 FakeLLM benchmark，补齐可回退的 checkpoint 式上下文压缩、最小运行时间线、可折叠的工具轨迹、Pi-style 动态运行预算、可审计的 hook 配置边界、FakeLLM CI 闸门和 MCP adapter 接口设计。

本版本继续采用 Pi 的设计思想，不照搬官方 Pi 的 TypeScript `agent_loop`，不引入官方 Pi SDK，也不把当前项目改造成 Pi 平台。默认 runtime 仍为 `native`；`pi` 继续作为可选的 Python Pi-style runtime。

本清单依据 [0.2.1 版本任务清单](../0.2.1-pi-runtime-architecture/0.2.1-pi-runtime-architecture.md) 的“下一个版本的优化建议”整理，已作为本次实施和验收基线。

实际执行记录：[0.2.2-pi-runtime-extension-实际执行.md](0.2.2-pi-runtime-extension-实际执行.md)。

## 3. 版本目标与设计原则

### 3.1 目标

1. 在上下文接近限制时，可以通过显式配置触发 checkpoint 压缩。
2. 压缩默认关闭；触发失败、取消或结果不合法时，能够安全回退。
3. 开发者和用户可以在 Webview 看到 turn、工具、首 token、耗时和错误分类等关键状态。
4. CI 无需真实模型密钥即可发现 runtime、协议、工具顺序和历史恢复回归。
5. 为未来远程工具接入定义最小 adapter 合同，但不在本版本引入网络工具执行风险。
6. 对 `piHooksFile` 形成明确的安全决策和最小可审计边界，默认拒绝隐式加载。

### 3.2 设计原则

1. **可选且可回退：** 新能力不应成为所有 runtime 的强制路径；压缩失败时优先保留可继续运行的原始上下文。
2. **状态与展示分离：** runtime 只发出稳定、脱敏的事件；Webview 负责聚合和展示，不反向依赖 Python 私有对象。
3. **默认安全：** 不根据工作区固定文件名自动执行 Python 代码，不把完整 prompt、工具参数值、工具结果和 API Key 写入日志或事件。
4. **先合同后接入：** MCP 先完成接口、错误模型和隔离测试，真实 MCP client、传输、鉴权和远程执行另立版本。
5. **行为优先于性能：** FakeLLM CI 只判断确定性行为；真实模型延迟、token 成本和工具选择质量单独作为性能数据，不用于本版本切换默认 runtime。
6. **最小改动：** 不重写现有 agent loop，不重构 native/langchain 正常逻辑，不改变 0.2.0 线性会话文件的读取兼容性。

## 4. 本版本不做

- 不将默认 runtime 从 `native` 切换为 `pi`。
- 不引入官方 Pi TypeScript 包或 Pi SDK。
- 不实现 session tree、fork、navigate、steer、follow-up 或并发会话控制流。
- 不把智能摘要压缩改为强制行为，不要求每轮额外调用摘要模型。
- 不默认自动执行 `piHooksFile`，不开放任意工作区 Python 文件加载。
- 不实现真实 MCP server/client、stdio/SSE/HTTP 传输、远程鉴权和远程工具执行。
- 不建设完整的历史事件持久化、日志检索平台或复杂监控面板。
- 本次补充不建设完整监控面板；仅在消息流中增加局部、低噪声、可折叠的工具轨迹组。
- 不以真实模型 benchmark 结果直接决定产品默认 runtime。

## 6. 详细任务

### PI22-01 固化 checkpoint 压缩合同与失败回退策略

**目标：** 在实现压缩算法前，明确 checkpoint、上下文快照、压缩结果和回退之间的边界，防止压缩逻辑直接修改会话历史或破坏工具调用链。

**计划内容：**

- 以现有 [pi_runtime.py](../../../agent/pi_runtime.py) 的 `AgentContext` 和 context pipeline 为基础，定义最小 checkpoint 数据：压缩前消息快照、触发原因、保留的 system/当前任务信息、压缩摘要或裁剪结果、版本/状态标识。
- 明确压缩只作用于本次 `LLMClient.chat` 请求上下文；除非通过明确的 session 更新动作，不自动覆盖 `.sessions/{id}.json`。
- 固化以下状态：`disabled`、`not_needed`、`completed`、`cancelled`、`failed`、`fallback`。
- 定义回退优先级：压缩结果无效、摘要调用失败、取消或超时后，恢复压缩前快照；如仍超过限制，再沿用现有确定性裁剪策略。
- 明确 system prompt、当前用户问题、成对的 tool call/tool result 和未完成工具调用的保留规则。
- 确定事件字段只传状态、原因、压缩前后消息数/估算 token 数和耗时，不传完整摘要正文。

**验收标准：**

- 文档和测试能说明一次压缩的输入、输出、失败和回退状态。
- 压缩前后的持久化历史默认不发生隐式变化。
- 非法或不完整的工具消息不会被压缩成可继续执行的假历史。
- 取消发生在压缩前、压缩中和压缩后时，均有稳定结果且不破坏后续对话。
- 默认配置关闭时，现有 native/pi 行为和上下文顺序不变。

### PI22-02 实现可选 checkpoint 式上下文压缩

**目标：** 在 Pi runtime 中提供最小、可关闭、可观测的压缩能力，为后续智能摘要保留接口，但不引入强制额外模型调用。

**计划内容：**

- 在 [pi_runtime.py](../../../agent/pi_runtime.py) 的请求前上下文管线中接入压缩检查点，保持 `transform_context → convert_to_llm → chat` 的外部顺序可追踪。
- 支持显式配置：是否启用、触发阈值、保留最近消息数量或 token 预算；未配置时使用关闭或现有默认行为。
- 优先复用现有 `compress_history`、`enforce_token_limit` 和 token 估算能力，不新增依赖。
- 将 checkpoint 处理与摘要策略解耦：本版本至少支持确定性裁剪/摘要占位；若需要额外 LLM 摘要调用，必须通过可注入接口、显式开关和失败回退完成。
- 压缩过程支持取消检查，不改变 session 文件格式，不影响 native/langchain 的默认路径。
- 增加 Pi Demo/FakeLLM 场景，验证压缩开启、关闭、触发、失败回退和恢复后继续对话。

**验收标准：**

- 配置关闭时，压缩代码不执行额外模型调用，现有输出和历史行为保持一致。
- 配置开启且达到阈值时，能够产生可验证的 checkpoint 状态，并保留 system prompt、当前任务和合法工具链。
- 压缩失败或被取消时，模型仍能收到合法上下文，且结果明确标记为 fallback/failed。
- 压缩不会把完整 prompt、摘要正文或工具结果写入 `agent_event`、CI 产物或普通日志。
- 至少覆盖：纯文本、单工具、连续工具、工具失败、超限、取消、历史恢复七类测试。

### PI22-03 增加 Webview runtime 事件时间线

**目标：** 把 0.2.1 已有的脱敏 `agent_event` 转换为低噪声的运行时间线，帮助定位首 token 慢、工具耗时高和错误发生位置。

**计划内容：**

- 在 [protocol.ts](../../../vscode-extension/src/protocol.ts) 保持 `agent_event` 向后兼容，补充 0.2.2 需要的可选统计字段和未知字段容错。
- 在 [main.js](../../../vscode-extension/src/webview/main.js) 维护当前 session 的有限事件列表，按 `event_seq` 排序；新 session、done、error 或重新初始化时清理边界明确。
- 最小展示字段：事件类型、相对耗时、turn/step、工具名、工具耗时、首 delta/首 token、结果长度和错误分类。
- 对高频 `message_update` 做聚合或限流，不展示完整 prompt、消息正文、工具参数值和工具结果。
- 时间线展示失败或收到未知事件时，不得阻塞正常回答、工具卡片和 done/error 状态。
- 保持现有 runtime 摘要与 `runtime_metric` 一致，区分 configured runtime 和 actual runtime。

**验收标准：**

- Demo Pi 完成一次文本回答和一次工具调用后，Webview 能看到有序的 start/turn/tool/end 关键事件。
- 事件重复、乱序、缺字段和未知事件不会导致 Webview 报错或时间线失控。
- 时间线有明确的最大条数/最大文本量限制，不持久化完整会话正文。
- 原有 `stream`、`tool_call`、`done`、`error` 展示和时序不回归。
- Python 协议测试、TypeScript 协议测试和 Webview 测试均覆盖该边界。

### PI22-04 `piHooksFile` 安全评估与显式配置边界

**目标：** 对 0.2.1 暂未开放的外部 hook 文件形成可审计决策，不因“可配置”而默认执行任意 Python 代码。

**计划内容：**

- 先记录是否开放的决策：若安全条件、错误隔离和 API 版本校验无法满足，则本版本只提供“禁用并说明原因”的配置状态。
- 若决定开放，仅接受用户显式配置的 `piHooksFile`，不扫描、不猜测、不自动加载工作区固定文件名。
- 约束路径必须位于明确 workspace 边界内；拒绝目录、符号链接逃逸、未知扩展名和越界路径。
- 加载前校验 hook API 版本和导出接口；导入异常、hook 异常和返回值非法时隔离到当前 session，不影响 native 或其他 session。
- 对 hook 可读取/可输出的数据建立白名单，禁止输出 API Key、完整上下文、工具参数值和完整工具结果。
- 增加配置说明、拒绝原因和安全测试；不提供绕过路径校验的隐藏开关。

**验收标准：**

- 任务结果包含明确的“开放/不开放”决策、理由、威胁边界和回滚方式。
- 未配置 `piHooksFile` 时无任何外部 Python 文件加载行为。
- 路径越界、符号链接逃逸、导入异常、API 版本不匹配和 hook 抛错均被拒绝或隔离。
- 安全失败不会改变 native runtime，也不会污染其他 session。
- 若最终不开放，代码和文档不会留下看似可用但实际不安全的半成品配置。

### PI22-05 建立 FakeLLM CI 回归闸门

**目标：** 将 0.2.1 的 FakeLLM benchmark 固化为无需 API Key 的自动化回归，持续验证 Pi 底层行为和协议边界。

**计划内容：**

- 在仓库 CI 配置中增加 Python 测试、ruff、VS Code 扩展测试、TypeScript 检查和 compile 的最小 workflow；优先使用已有依赖和脚本。
- 固化 FakeLLM 场景：文本回答、单工具、连续工具、工具失败、取消、最大步数、上下文压缩开启/关闭、历史恢复、Pi Demo。
- 让 CI 检查 `configured_runtime` 与 `actual_runtime`、工具顺序、必需工具是否执行、结束状态、协议事件脱敏和历史角色顺序。
- 产出 JSONL 或测试报告时仅保存脱敏指标；禁止保存 API Key、完整 prompt、工具参数值和工具结果。
- 规定真实模型 benchmark 作为手工/定期性能任务，不作为默认 PR 必需条件，也不影响产品默认 runtime。
- 增加失败诊断信息：场景名、runtime、失败阶段和错误分类，避免只报告一个总失败。

**验收标准：**

- CI 在无 `INTERVIEW_API_KEY` 时可以完成关键 Python/TS 回归。
- 任一 runtime 实际回退、必需工具未执行、工具顺序错误、事件泄漏或历史损坏都能使对应任务失败。
- 同一 FakeLLM 场景重复运行结果稳定，不依赖网络和真实模型服务。
- CI 产物可以帮助定位失败，但不包含敏感正文。
- 本地命令与 CI 命令一致或有明确映射，开发者可以在提交前复现。

### PI22-06 设计 MCP adapter 合同与隔离测试

**目标：** 为未来工具 provider 扩展定义稳定边界，借鉴 Pi 的工具生命周期思想，但不在 0.2.2 接入真实 MCP 网络能力。

**计划内容：**

- 在 [tool_registry.py](../../../agent/tool_registry.py) 或与现有职责匹配的模块中，设计最小 adapter 合同：工具发现、名称/描述/schema、调用、结果、错误、超时、取消和关闭。
- 明确 MCP 工具与本地工具的统一内部结果格式，保留错误分类和是否可重试信息；不允许 adapter 直接修改 AgentContext 或 session 文件。
- 设计 provider 能力声明和版本兼容字段，避免把 MCP 私有字段直接暴露给 `PiToolExecutor`。
- 使用 fake adapter 做隔离测试：发现失败、schema 非法、调用超时、取消、工具错误、结果过大、重复工具名和 provider 关闭。
- 明确安全前置条件：权限、工作区边界、网络访问、凭据存储、结果脱敏和审计日志在后续接入前必须单独评审。
- 不添加 MCP 依赖、不启动外部服务、不修改现有本地 ToolRegistry 的默认行为。

**验收标准：**

- 有一份接口说明能明确 adapter 与 `ToolRegistry`、`PiToolExecutor`、`agent_event` 的责任边界。
- fake adapter 的成功、错误、超时、取消和关闭场景均可测试，且不需要网络。
- MCP 未启用时现有本地工具行为完全不变。
- 未通过权限和凭据安全评审前，不存在默认可执行的远程工具路径。
- adapter 不泄漏完整远程结果、凭据或内部 provider 对象。

### PI22-08 小思考轨迹折叠与工具调用分组

**目标：** 参考图一、图二改善运行过程的可读性，让用户可以在不打断主回答的情况下查看每组模型运行轨迹。

**计划内容：**

- 每次模型等待/工具运行创建一个小思考组，使用原生 `details/summary` 提供折叠入口。
- 将该组内的命令、工具名称、参数摘要和结果摘要统一写入折叠内容；轨迹完成后保留在消息流中，不因下一段文本到达而删除。
- 两段面试官输出之间的连续工具调用只生成一个轨迹组；下一段文本输出开始时结束当前组并创建新的面试官气泡。
- 运行态显示小思考球，完成态显示已完成步骤数；不把完整 prompt、密钥或未脱敏内部事件放入 Webview。
- 保持现有 `stream`、`tool_call`、`done`、`error` 和取消时序，轨迹展示异常不能阻塞回答。

**验收标准：**

- 文本输出前后的工具调用均有一个可展开/收起的轨迹入口。
- 同一段输出之间的多次工具调用集中在同一个折叠组，不产生重复独立大卡片。
- 工具调用完成后轨迹仍可查看，且未完成/完成状态可区分。
- 无工具调用时不残留空轨迹组；取消和错误时已产生的轨迹仍可安全收尾。
- Webview 模板测试、TypeScript 检查和 compile 均通过。

### PI22-09 Pi-style 自然结束与独立运行预算

**目标：** 消除 Pi runtime 复用 native 默认 8 回合限制导致的过早停止，同时保留明确的循环安全边界。

**计划内容：**

- Pi runtime 默认最大模型回合数调整为 32；native runtime 仍保持原有 8 回合默认值。
- Pi 每轮模型没有工具调用时立即结束；最大回合数只用于防止模型持续产生工具调用的异常循环。
- 增加 `interview.piMaxSteps` / `pi_max_steps` 配置，默认 32，允许用户按项目复杂度调整安全预算。
- 保留达到安全预算后的明确 fallback，不伪装成正常完成；增加默认值、透传和上限触发测试。
- 不复制 Pi 的完整 agent loop；只吸收“无工具调用自然结束、工具循环由安全阀兜底”的运行思想。

**验收标准：**

- Pi 默认配置可连续完成超过 8 个工具回合的 FakeLLM 场景，不提前返回 native 的最大步数提示。
- Pi 收到无工具调用的模型回答后立即结束，不为了消耗预算继续请求模型。
- 自定义 `piMaxSteps` 能透传到 Python；达到该值时仍能安全结束并保留明确提示。
- native、langchain 和旧客户端未传新字段时行为保持兼容；默认 runtime 仍为 native。
- 运行时测试、SessionStore 配置测试、FakeLLM benchmark 和全量回归均通过。

### PI22-07 补齐 0.2.2 文档、验收和发布闸门

## 8. 0.2.2 完成定义（Definition of Done）

只有同时满足以下条件，才可以将版本标记为完成：

1. checkpoint 压缩合同、失败回退、取消和持久化边界已有文档与测试。
2. Pi runtime 支持可选压缩，默认关闭；压缩失败不会破坏合法上下文和历史文件。
3. Webview 能展示脱敏、限量、有序的关键 runtime 事件，且不影响原有回答和工具展示。
4. `piHooksFile` 有明确安全决策；未满足安全条件时默认不执行外部文件。
5. FakeLLM CI 在无 API Key、无网络依赖下覆盖关键 runtime、工具、压缩、恢复和协议场景。
6. MCP adapter 只有接口合同和隔离测试，不产生默认远程工具执行路径。
7. Webview 运行轨迹按输出间分组、可折叠、完成后保留，且不泄漏敏感正文。
8. Pi runtime 无工具调用时自然结束，默认 32 回合仅作为可配置安全阀；native 默认行为不变。
9. 0.2.1 全量回归仍通过，新增 Python/TS 测试、lint、类型检查和扩展编译均通过。
10. 默认 runtime 仍为 `native`，0.2.2 不引入官方 Pi SDK、不改变旧 session JSON 读取兼容性。
11. 文档和实际执行记录完整，能够给出明确的验收步骤、验收标准和未覆盖风险。

## 9. 0.2.2 验收步骤

1. 执行 Python 全量测试和 lint，确认既有 0.2.1 回归无新增失败。
2. 执行 VS Code 扩展测试、TypeScript 检查和 compile，确认协议与 Webview 逻辑通过。
3. 在无 `INTERVIEW_API_KEY`、无网络依赖条件下执行 FakeLLM CI 对应命令，确认 native/pi 关键场景稳定通过。
4. 在 Demo Mode 选择 `agentRuntime=pi`，分别关闭和开启压缩，确认关闭时行为不变，开启后能看到压缩状态及必要的回退结果。
5. 使用文本、单工具、连续工具、工具失败、取消和超限场景检查 Webview 时间线，确认事件有序、限量、脱敏。
6. 未配置 `piHooksFile` 时检查无外部文件加载；使用越界路径、符号链接、错误 API 版本和抛错 hook 验证均被拒绝或隔离。
7. 执行 fake MCP adapter 隔离测试，确认发现、调用、错误、超时、取消和关闭不需要网络，且本地工具行为不变。
8. 检查旧 `.sessions/{id}.json` 恢复、继续对话和保存结果，确认消息角色顺序与 0.2.0 兼容。
9. 在 Demo Mode 的 Pi runtime 中制造连续工具调用：确认多次调用收纳于一个可折叠轨迹组，完成后仍可展开查看。
10. 使用超过 8 个工具回合的 FakeLLM 场景验证 Pi 不因 native 的 8 回合限制提前结束；再将 `interview.piMaxSteps` 调低，确认安全阀仍有效。

## 10. 0.2.2 版本任务清单本身的改进建议

- 将“摘要压缩质量”和“底层压缩正确性”拆开验收：0.2.2 先保证状态、回退和上下文合法性，不用主观评价摘要文案决定版本是否完成。
- 时间线先限制为调试型最小视图，稳定事件字段和容量上限后，再考虑筛选、持久化和可视化增强。
- `piHooksFile` 必须以安全决策为前置交付物；如果路径隔离、权限和错误边界无法证明，应保留关闭状态，不为了完成配置项而降低安全门槛。
- MCP adapter 只做合同和 fake 隔离测试，避免接口设计、传输接入、鉴权和远程工具治理同时进入一个版本。
- CI 失败信息应优先指出场景和状态差异，避免只依赖大段日志，降低后续排查成本。

## 11. 下一个版本的优化建议（0.2.3）

- 基于 0.2.2 的压缩指标和真实模型数据，评估摘要质量、token 节省、延迟和失败率，再决定是否引入可选 LLM summarizer。
- 评估是否将 runtime 事件从内存时间线扩展为可查询的 trace/诊断记录，但先明确隐私、保留周期和存储上限。
- 若 `piHooksFile` 安全开放方案通过评审，再增加 hook API 版本演进、权限分级和配置迁移策略。
- 基于 MCP adapter 合同选择并隔离一个最小 provider，先做本地受控连接，再评估远程工具权限、凭据和审计。
- 继续收集 native/pi 在相同 Prompt、工具和模型条件下的可比 benchmark，再讨论产品默认 runtime 策略。
- 根据 Pi 运行预算的实际命中率，进一步设计按工具循环、耗时和上下文压力动态调整安全阀的策略。

## 12. 后续可扩展的优化建议

- 会话从线性 JSON 演进为兼容旧格式的 checkpoint/session tree，支持分支、回溯和压缩节点可见性。
- 增加 steer、follow-up 和并发取消等交互控制语义，建立明确的协议时序和竞态测试。
- 建立跨 runtime 的统一 trace id、结构化日志、指标采集和问题诊断查询。
- 支持多工具 provider 的权限、超时、重试、速率限制和结果大小治理。
- 增加压缩质量评测集、工具选择质量评测集和真实模型成本回归。
- 当正确性、工具成功率、可观测性和成本数据连续达到门槛后，再独立评估将默认 runtime 从 native 切换为 pi。
