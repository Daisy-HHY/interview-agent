# 0.2.1 Pi-style runtime 实际执行记录

## 1. 执行范围

本次按 [0.2.1 任务清单](0.2.1-pi-runtime-architecture.md) 完成 Pi-style runtime 底层架构优化。未引入官方 Pi SDK，未切换默认 runtime，未实现 MCP、session tree、steer/follow-up、智能摘要压缩和完整事件时间线 UI。

## 2. 实际修改内容

| 任务 | 实际结果 |
|---|---|
| PI-01 | 保留 `AgentRuntime` 外部边界，补充 context、事件和 session 历史职责边界；未复制第二套通用 agent loop |
| PI-02 | `SessionStore` 支持显式 `Pi` 配置、按 session 创建 event sink；不自动执行工作区 Python hook 文件 |
| PI-03 | 固化 `transform_context → convert_to_llm → LLMClient.chat` 流程，并补充顺序、取消和历史测试 |
| PI-04 | 新增脱敏 `agent_event` 协议；内部事件增加 event sequence 和相对耗时，协议只输出统计摘要 |
| PI-05 | Demo Mode 下 `agent_runtime=pi` 实际创建 `PiAgentRuntime`，并使用 FakeLLM；前端按实际 runtime 更新摘要 |
| PI-06 | 新增公开 `restore_messages()`，native/langchain/pi 均支持，SessionStore 不再直接写 runtime 私有 `_messages` |
| PI-07 | benchmark 新增 `--fake-llm`，无 API Key 可运行；固定 FakeLLM 先执行项目读取工具再结束 |
| PI-08 | README 增加 Pi-style 边界说明、能力对照表、FakeLLM benchmark 命令和本次执行记录 |

另外，完整回归首次发现一个原有的静态 prompt 测试与提示文本不一致的问题，补充了明确的“不是 Interview Agent 插件自身源码阅读助手”边界文案，使既有测试恢复通过；没有改变面试流程逻辑。

## 5. 验收步骤

1. 执行 Python 全量测试和 lint，确认结果分别为 `253 passed, 1 skipped` 和 `All checks passed`。
2. 执行 VS Code 扩展测试、TypeScript 检查和 compile，确认无失败。
3. 在无 `INTERVIEW_API_KEY` 的环境执行 `--runtime pi --fake-llm`，确认输出 JSONL 且 `runtime=pi`、`status=done`、`required_tool_used=true`。
4. 在 Demo Mode 选择 `agentRuntime=pi`，开始一轮对话，确认 UI runtime 摘要显示实际 `pi`，且不会发起真实模型请求。
5. 检查历史恢复：使用已有 `.sessions/{id}.json` 继续对话，确认消息顺序和 system prompt 保持有效。
6. 检查 `agent_event`：确认事件可以解析，但事件内容不包含 API Key、完整 prompt、工具参数值或完整工具结果。

## 6. 验收标准

- Pi runtime 仍通过项目统一的 `AgentRuntime` 接口运行。
- SessionStore 可以显式注入 Pi 配置和事件出口。
- Demo Mode 下 Pi 不再强制回退 native。
- context pipeline 顺序稳定，历史恢复不依赖 runtime 私有字段。
- `agent_event` 仅发送脱敏统计字段，不改变现有 stream/tool_call/done 时序。
- FakeLLM benchmark 不需要 API Key，且能验证工具调用行为。
- 默认 runtime 仍为 `native`。
- Python、TS 测试、lint、类型检查和编译全部通过。

## 7. 未覆盖风险

- 外部 Python hook 文件尚未开放；如果后续开放，需要先完成路径限制、导入异常隔离和执行权限评审。
- FakeLLM 只能验证行为和协议闭环，不能替代真实模型的延迟、工具选择质量和 token 成本评估。
- 完整事件时间线 UI、智能 compaction、MCP 和 session tree 仍属于后续版本。
