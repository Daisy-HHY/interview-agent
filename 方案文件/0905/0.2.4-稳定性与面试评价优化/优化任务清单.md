## 1. 目标与范围

本清单对应项目检查发现的六类优先问题：历史裁剪破坏工具配对、业务历史受压缩影响、密钥与敏感文件保护不足、报告评价依据不足、工具资源上限不完整、benchmark 统计与样本隔离不足。

先修复影响默认使用路径的确定性问题，再改进报告的可信度。以下任务都是计划，不表示已开发、已验收或已获代码修改授权。

本版本保持以下边界：

- 默认 runtime 继续为 `native`；Pi 压缩与动态预算不因此默认开启。
- 保留现有用户改动和旧会话 JSON 消息数组格式，不批量重写历史文件。
- 不引入数据库、新 Agent 框架、远程 tracing、多 Agent 编排或真实 MCP 传输。
- 普通报告导出保持本地可用；不得悄悄增加一次付费模型调用。
- 真实模型验收、依赖安装、VSIX 打包、提交和发布分别记录，不能用单测通过替代。

## 2. 开发前需要处理的现有逻辑冲突

| 用户目标 | 当前逻辑或约束 | 风险 | 建议取舍 |
|---|---|---|---|
| 长对话仍能合法请求模型 | 历史裁剪逐条删除；既有测试还要求至少保留四条消息 | 工具调用与结果被拆开；四条消息也可能超限 | 用语义完整性和预算检查替代固定条数约束；先新增失败用例，再调整旧测试 |
| 历史恢复与报告保留原始信息 | native 和 langchain 在用于存档的消息上做裁剪 | 初始 JD、回答原文永久丢失 | 模型请求使用裁剪副本；原始业务历史继续供保存和报告使用 |
| 历史保存更安全 | 保存直接覆盖原 JSON，恢复失败时静默跳过 | 中途失败可能导致旧会话不可恢复 | 同目录临时文件写完再原子替换；失败保留旧文件并提示，不能偷偷当新会话继续覆盖 |
| 密钥进入加密存储 | 当前配置读取同步，密钥保存在普通设置中 | 简单替换可能导致首次启动拿不到密钥，或迁移失败后丢失配置 | 异步读取加密存储并等待完成；兼容旧配置，不在未成功保存时清除旧值 |
| 阻止敏感内容被工具读取 | 当前只限制部分工具的工作区路径，未统一敏感路径策略 | 边界内的凭证、会话和报告也可能进入模型 | 三个文件工具共用窄范围策略；不一刀切禁止所有隐藏目录或配置文件 |
| 报告真正评价回答 | 现有导出为同步、本地、确定性的摘录与规则文本 | 直接接模型会改变费用、耗时、失败方式和数据发送范围 | 本版先明确区分摘录、已有反馈、待考察项；独立模型评价作为下一阶段可选能力 |

“完整存档”和“模型始终携带完整历史”是不同要求：本版保证存档不因压缩丢失，模型上下文仍受预算约束。不得把任意长度的简历、JD 或历史永久无上限地放进每次请求。

P0 表示本版本应先完成的可靠性和访问边界任务；P1 表示随后完成的产品和验收任务。优先级不代表已发生线上事故。

| 编号 | 优先级 | 任务 | 依赖 | 完成标准摘要 |

| OPT-02 | P0 | 分离业务存档与模型请求上下文 | OPT-01 | 裁剪、保存、重启后 JD 与回答原文仍在 |
| OPT-03 | P0 | 会话原子保存与异常恢复 | 无；与 OPT-02 联合验收 | 写入失败不破坏旧会话，坏文件不被静默覆盖 |

## 4. 分项实施任务

### OPT-01：按完整工具调用组裁剪上下文

**涉及文件：** [history.py](../../../agent/history.py)、[agent_loop.py](../../../agent/agent_loop.py)、[pi_runtime.py](../../../agent/pi_runtime.py)、[langchain_runtime.py](../../../agent/langchain_runtime.py)。  
**测试入口：** [test_history.py](../../../agent/tests/test_history.py)、[test_agent_loop.py](../../../agent/tests/test_agent_loop.py)、[test_pi_runtime.py](../../../agent/tests/test_pi_runtime.py)。

- [ ] 先将“删除 assistant 调用却留下 tool 结果”的复现写成失败测试，覆盖一个调用和多个调用。
- [ ] 将 assistant 工具调用及其对应结果作为不可拆分的组处理；旧组可整体移除，最近有效组应完整保留。
- [ ] 明确保留系统提示、当前用户问题及本轮工具链；不能把“最后一条消息”直接等同于“当前用户问题”。
- [ ] 复用和核对 Pi 已有的工具消息修复逻辑，避免 shared history 与 Pi 各自执行互相冲突的修复。
- [ ] 更新固定保留四条消息的测试，使其验证语义完整性，而不是固定数量。
- [ ] 必须保留的最小上下文仍超预算时，返回可解释的超限结果；不伪称已满足上限，不默默丢弃当前问题。

**验收标准：** 发往模型的每个工具结果都能匹配对应调用；调用要求的结果完整；低预算、长工具结果、多调用及取消场景都不破坏配对。原始输入对象不被裁剪函数修改。估算 token 上限不能被解释为服务商实际 token 的精确保证。

### OPT-02：分离业务存档与模型请求上下文

**涉及文件：** [agent_loop.py](../../../agent/agent_loop.py)、[langchain_runtime.py](../../../agent/langchain_runtime.py)、[pi_runtime.py](../../../agent/pi_runtime.py)、[runtime.py](../../../agent/runtime.py)、[session.py](../../../agent/session.py)。  
**测试入口：** [test_agent_loop.py](../../../agent/tests/test_agent_loop.py)、[test_langchain_runtime.py](../../../agent/tests/test_langchain_runtime.py)、[test_pi_runtime.py](../../../agent/tests/test_pi_runtime.py)、[test_session.py](../../../agent/tests/test_session.py)。

- [ ] 先证明当前 native 长历史裁剪后，存档会丢失早期消息。
- [ ] 保持 runtime 的 `messages` 表示该 runtime 已记录的业务历史；压缩与裁剪仅生成模型请求副本。
- [ ] 核对三个 runtime 的实际行为，不假定 LangChain 已记录全部内部工具事件；本任务不顺带扩展其持久化事件范围。
- [ ] 保持旧消息数组可读取；已被旧版本丢弃的内容无法补回，不能宣称迁移会自动恢复。
- [ ] 覆盖正常完成、停止、模型异常和重启后的保存与继续问答。
- [ ] 记录完整存档导致磁盘和加载量增加的取舍，本版不自动清理或裁剪用户历史。

**验收标准：** 用带唯一标记的 JD、简历摘要和多轮回答触发上下文裁剪，保存后重新创建 SessionStore，标记仍完整存在；模型收到的是受控副本；报告仍能获取首次输入。两者不共享会被修改的可变内容。

### OPT-03：会话原子保存与异常恢复

**涉及文件：** [session.py](../../../agent/session.py)、[main.py](../../../agent/main.py)、必要时的 [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts)。  
**测试入口：** [test_session.py](../../../agent/tests/test_session.py)、[test_main.py](../../../agent/tests/test_main.py)。

- [ ] 先注入序列化失败、写入失败和替换失败，复现并保护已有有效会话。
- [ ] 在目标文件同一目录写临时文件，完成写入并关闭句柄后原子替换；复用 Python 标准库。
- [ ] 失败时只清理本次创建的临时文件，不删除旧存档，不批量清理其他历史。
- [ ] 对合法 JSON 但结构错误、空值元素、无效首条消息等输入进行校验。
- [ ] 将“会话不存在”和“会话损坏”区分开；损坏文件保留，提示无法恢复，不自动用空会话覆盖。
- [ ] 写入错误复用现有错误通知，不在日志中输出完整会话内容。

**验收标准：** 各类失败后旧文件内容与失败前一致；成功后新文件可完整解析；Windows 下不存在临时文件仍打开导致替换失败的问题。原子替换测试不等同于已验证所有硬件断电场景。

**测试入口：** [test_tools.py](../../../agent/tests/test_tools.py)。

### OPT-07：修正 benchmark 统计与隔离

**涉及文件：** [runtime_benchmark.py](../../../agent/runtime_benchmark.py)、[llm_client.py](../../../agent/llm_client.py)、必要时的 [protocol.py](../../../agent/protocol.py)。  
**测试入口：** [test_runtime_benchmark.py](../../../agent/tests/test_runtime_benchmark.py)、[test_llm_client.py](../../../agent/tests/test_llm_client.py)。

- [ ] 先测试“native 无预算 + Pi 一次命中”：有效预算样本数应为 1，命中率应为 100%，不是 50%。
- [ ] 区分总样本数、有效样本数、缺失数；无有效预算数据时返回未知，不写 0%。
- [ ] 按实际 runtime 汇总，保留配置 runtime；FakeLLM 的 LangChain 回退记录不得混作 LangChain 成绩。
- [ ] 每个样本独立初始化上下文，不恢复旧 benchmark 会话，也不把测试会话写进用户历史。
- [ ] 同一评测重复运行时起始历史一致；baseline 和 compaction 使用相同的初始样本及工具条件。
- [ ] 区分自然完成、预算耗尽、工具不足、错误和回退；不能仅凭 `run()` 返回就计为任务成功。
- [ ] 有服务商用量时记录实际输入/输出 token；没有则明确缺失，保留估算字段并注明口径；流式服务不支持用量时可降级。
- [ ] 增加可验证关键信息的样本，而不只注入重复的长文本；质量仍需独立人工或参考答案检查。

**验收标准：** 分母、分组和缺失处理准确；重复运行不污染历史；预算耗尽不会计为自然完成；同样本可比较；输出不包含密钥、完整简历、代码和工具结果。真实质量与费用结论必须由真实模型样本支持。

### OPT-08：报告内容可信化

**涉及文件：** [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts)、[README.md](../../../README.md)。  
**测试入口：** [report.test.ts](../../../vscode-extension/test/report.test.ts)、[sessionTitle.test.ts](../../../vscode-extension/test/sessionTitle.test.ts)。

- [ ] 先增加“只提供 JD、尚未回答”“同技术但不同回答”“只出现 JavaScript”三类用例。
- [ ] 把回答原文摘录明确标成摘录，不把它包装为模型评分。
- [ ] 区分 JD 提到的技术、候选人自述的技术与对话实际考察点；只有关键词出现不能证明掌握或薄弱。
- [ ] 技术识别避免子串误判，例如 JavaScript 不能自动推导出 Java。

**验收标准：** 报告不会把 JD 要求写成候选人事实；不会仅凭回答轮数、技术词或回答长度判定能力；引用能对应真实消息；无有效回答时不生成虚假薄弱点。真正的语义评价列为下一版本独立任务。

## 7. 本版本改进建议

1. 先修默认 native 的确定性缺陷，再考虑 Pi 的默认值或动态预算；避免优化实验分支时遗漏主路径。
2. 将“完整存档”“合法请求上下文”“可追溯报告”作为三个独立验收目标，不能因一个测试通过就推断另两个成立。
3. 本版报告先做到不误导，再做新的评价模型。仅把固定建议换成另一套固定建议不能算语义评价完成。
4. 优先复用标准库、SecretStorage、现有协议与测试框架，不引入数据库、索引服务或新观测平台。
5. 真实模型配对评测是后续决策依据；缺少真实结果时保持开关默认关闭，并明确未验收项。

## 8. 下一个版本的优化建议

| 顺序 | 扩展方向 | 最小范围 | 依赖与验收门槛 |
|---|---|---|---|
| 1 | 单题语义评价 | 用户主动触发；复用现有模型调用能力；输出考察点、正确部分、回答证据、具体缺口和建议追问 | OPT-02、OPT-08；评价引用能定位到原文，坏响应／超时／取消可回退本地报告；费用和数据发送范围明确 |
| 2 | 薄弱点复练 | 从一条有依据的缺口进入一次针对性练习 | 前项评价可信；再次练习能判断该缺口是否改善，不直接比较无依据的总分 |
| 3 | 能力覆盖与面试进度 | 区分已考察、待考察和需复练，减少重复追问 | 统一技术点与问答关联；不能把未考察记为不会 |
| 4 | JD—项目证据关联 | 分开记录岗位要求、简历自述、项目证据 | 工具边界完成；每个“代码已确认”项有可定位来源，查不到时标注未确认 |
| 5 | 完整面试流程 | 轮数或时长目标、主动结束、整场复盘 | 覆盖状态可靠；达到目标可收束、取消可恢复，不以 runtime 最大步数充当面试轮数 |

独立模型评价是新的产品能力，不因生成本清单自动启用；先明确触发方式、数据结构、成本和失败行为，再安排开发。不先搭建多个面试官或评分 Agent。

## 9. 后续可扩展的优化建议

| 方向 | 适合启动的条件 | 最小实现与边界 |
|---|---|---|
| 多工作区项目选择 | 用户实际需要同时准备多个项目 | 从现有工作区选择本次项目；会话与工具根目录一致，不默认跨项目读取 |
| 跨会话成长记录 | 单题评价和复练已足够稳定 | 按同一能力查看有证据的变化；不先新增账号系统或云同步 |
| 语音面试 | 文字练习闭环成熟，用户明确需要口述训练 | 先语音输入与转写确认；明确音频是否外发、是否保存，不默认常驻录音 |
| 按行读取与代码证据跳转 | 前 200 行不能支撑真实追问 | 在现有只读工具增加受限行范围，返回真实路径和行号，不先做全仓知识图谱 |
| 真实 MCP 工具 | 出现内置工具无法满足的明确数据来源 | 基于现有 adapter 接入单个 provider，再验证传输、鉴权、超时和访问权限 |
| 多角色面试 | 单一面试官确实难以覆盖明确的独立职责 | 先比较单模型分阶段流程的效果，再评估编排；不为了扩展性新增框架 |
| 受控诊断导出 | 内存时间线无法定位实际故障 | 用户主动导出脱敏事件，先确定容量与保留周期，不默认存完整 trace |

这些方向均是建议储备，不属于本版本必做任务，也不代表已授权实现。
