# Interview Agent 0.1.12 版本开发任务清单

计划日期：2026-08-31

## 1. 本版本结论

0.1.12 的核心目标是：**先用真实运行指标判断 LangChain runtime 是否稳定；稳定后再把默认 runtime 从 `native` 改为 `langchain`。**

本版本不直接假设 LangChain 已可默认启用。0.1.11 只是完成了可选 runtime、工具 adapter 和假 agent 验证，实际执行记录中仍有一个关键风险：**还没有使用真实 API Key 调用 LangChain runtime 做在线模型请求**。因此 0.1.12 必须先补一条可复现的真实指标闸门。

执行原则：

1. 如果 LangChain 真实指标达标，则执行默认 runtime 切换。
2. 如果 LangChain 真实指标不达标，则保留 `native` 默认，只沉淀指标、诊断面板和端到端测试。
3. MCP 只做可复用边界设计和约束测试，不提前接入真实 MCP 工具。

## 2. 本版本范围

### 2.1 必做

1. 增加真实 LangChain runtime 指标评估脚本或测试入口。
2. 用同一模型配置分别跑 `native` 与 `langchain`，记录模型耗时、工具耗时、首 token 耗时、总耗时、错误分类和 token 粗估。
3. 指标通过后，把默认 runtime 改为 `langchain`；不通过则保留 `native`。
4. 补 VS Code 端到端 UI 自动化，覆盖 runtime 切换、思考球工具折叠、上传 OCR、会话恢复。
5. 增加最小诊断面板，展示最近一轮或当前会话 runtime 指标。
6. 优化首面板模型配置摘要，使其根据 VS Code Settings 中的配置自动更新。
7. 收紧工具 adapter 的内部协议，让当前内置工具和未来 MCP 工具都走同一个最小边界。

### 2.2 暂不做

1. 不接入 LangSmith、远程 tracing 或外部观测平台。
2. 不把会话存储迁移到 LangGraph checkpoint。
3. 不引入 AutoGen / AgentScope。
4. 不实现真实 MCP client/server。
5. 不为诊断面板做长期数据库存储；先使用当前会话内存指标和 Output Channel 日志。

## 3. LangChain 默认切换闸门

### 3.1 真实运行样本

使用相同 workspace、相同模型配置、相同问题，对 `native` 和 `langchain` 各执行至少 5 轮真实模型调用。

统一问题：

```text
请读取当前项目结构，结合项目中的 Agent runtime 和工具实现，追问一个和工具调用或会话恢复相关的技术问题。
```

必须覆盖：

1. 至少一次 `list_directory` 工具调用。
2. 至少一次 `search_code` 或 `read_file` 工具调用。
3. 至少一次流式输出。
4. 至少一次会话落盘后恢复再继续对话。
5. 至少一次取消操作，验证 stop 后不会继续追加大量输出。

### 3.2 指标采集字段

| 指标 | 说明 | 采集位置 |
|---|---|---|
| `runtime` | `native` / `langchain`，记录实际运行值，不能只记录配置值 | [session.py](../../../agent/session.py)、[main.py](../../../agent/main.py) |
| `model_elapsed_ms` | 单轮模型请求累计耗时 | [llm_client.py](../../../agent/llm_client.py)、[langchain_runtime.py](../../../agent/langchain_runtime.py) |
| `first_delta_ms` | 从发送 chat 到首个 stream delta 的耗时 | [main.py](../../../agent/main.py)、[agentClient.ts](../../../vscode-extension/src/agentClient.ts) |
| `tool_elapsed_ms` | 每次工具 start 到 end 的耗时 | [agent_loop.py](../../../agent/agent_loop.py)、[langchain_tools.py](../../../agent/langchain_tools.py) |
| `total_elapsed_ms` | 从 chat 进入到 done / error / cancelled 的总耗时 | [main.py](../../../agent/main.py)、[agentClient.ts](../../../vscode-extension/src/agentClient.ts) |
| `estimated_tokens` | 复用现有历史 token 粗估逻辑，不新增 tokenizer 依赖 | [history.py](../../../agent/history.py) |
| `error_kind` | `auth` / `network` / `rate_limit` / `timeout` / `tool` / `runtime` / `ocr` / `unknown` | [llm_client.py](../../../agent/llm_client.py)、[main.py](../../../agent/main.py) |

### 3.3 默认切换通过标准

只有全部满足时，才把 `interview.agentRuntime.default` 改为 `langchain`：

1. `langchain` 真实运行 5 轮中至少 4 轮成功完成 `done`，且不能发生依赖缺失回退。
2. 工具调用通知必须成对出现：每个 `tool_call.start` 都有对应 `tool_call.end` 或明确错误。
3. 思考球折叠详情中能看到工具名、参数、结果摘要。
4. `first_delta_ms` 不超过 `native` 均值的 1.5 倍；如果模型供应商波动较大，绝对值不超过 15 秒。
5. `total_elapsed_ms` 不超过 `native` 均值的 1.5 倍；单轮绝对值不超过 90 秒。
6. 会话恢复后继续使用实际配置 runtime，不因恢复历史退回错误 runtime。
7. 取消操作后 3 秒内进入 `cancelled` 或停止后续工具执行。
8. `npm run package` 后 VSIX 体积相对 0.1.11 增量不超过 150 KB；若超过，必须说明原因并复核 `.vscodeignore`。

未达标处理：

1. 保留 `native` 默认值。
2. 诊断面板仍显示 `langchain` 的失败指标和错误分类。
3. 任务记录里写清失败原因、复现命令和下一步修复建议。

### 4.3 任务三：端到端 UI 自动化

| 场景 | 覆盖内容 | 建议方式 |

4. 仍保留一次手工验收系统文件资源管理器拖入文件，因为 OS 级拖拽不适合在 VS Code 扩展测试里强行模拟。

### 4.5 任务五：工具 adapter 的 MCP 可复用边界

当前 [base.py](../../../agent/tools/base.py) 已有 `Tool` / `ToolRegistry` 最小协议，0.1.12 不需要提前实现 MCP。只需要把边界约束清楚，避免 LangChain adapter 写死到内置工具。

| 任务 | 说明 | 相关文件 |
|---|---|---|
| 收紧 Tool 契约 | 明确工具必须提供 name、OpenAI function schema、execute kwargs -> string | [base.py](../../../agent/tools/base.py) |
| Adapter 不反向依赖 | LangChain adapter 只依赖 ToolRegistry，不依赖具体内置工具类 | [langchain_tools.py](../../../agent/langchain_tools.py) |
| MCP 边界文档 | 写清未来 MCP 工具只需要适配为 Tool 后注册，不进入 runtime 主循环 | 可新增 [工具适配边界.md](./工具适配边界.md) |
| 契约测试 | 用 fake MCP-like tool 验证注册、schema 输出、LangChain 包装和执行 | [test_langchain_runtime.py](../../../agent/tests/test_langchain_runtime.py) 或新增测试 |

验收标准：

1. 不引入 MCP SDK 或真实 MCP 依赖。
2. 内置工具、LangChain adapter、未来 MCP-like fake tool 共用同一个 `Tool` 边界。
3. runtime 不知道工具来源，只通过 `ToolRegistry` 调用。

### 4.6 任务六：首面板模型配置自动更新

当前首面板“模型配置”摘要来自 Extension Host 读取的 `interview.*` 配置。0.1.12 需要让用户在 VS Code Settings 中修改模型、baseUrl、Demo Mode、runtime 后，首面板自动刷新配置摘要，不需要手动重开面板。

| 任务 | 说明 | 相关文件 |
|---|---|---|
| 监听配置变化 | 监听 `workspace.onDidChangeConfiguration`，只处理 `interview.*` 相关变更 | [extension.ts](../../../vscode-extension/src/extension.ts) |
| 推送配置快照 | 配置变化后向当前 Webview 推送最新 `config` 快照，不包含 API Key 明文 | [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) |
| 更新首面板摘要 | 首面板模型配置摘要自动显示最新模型名、baseUrl 状态、Demo Mode、runtime | [main.js](../../../vscode-extension/src/webview/main.js)、[index.html](../../../vscode-extension/src/webview/index.html) |
| Agent 重启策略 | 影响 Python 子进程的配置变化后，下一轮对话使用新配置；如已有 Agent 运行中，先提示或延迟到下一轮重启 | [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts)、[agentClient.ts](../../../vscode-extension/src/agentClient.ts) |
| 回归测试 | 覆盖配置变化后 `postConfig` 被触发、摘要刷新、API Key 不回显 | [webview-template.test.ts](../../../vscode-extension/test/webview-template.test.ts)、新增或扩展 Host 测试 |

验收标准：

1. 修改 VS Code Settings 里的 `interview.model` 后，首面板摘要自动显示新模型名。
2. 修改 `interview.baseUrl` 后，首面板显示是否使用自定义 base URL，但不泄漏敏感 token。
3. 修改 `interview.demoMode` 或 `interview.agentRuntime` 后，摘要自动更新，并且下一轮对话实际使用新配置。
4. 正在生成回答时修改配置，不中断当前回答；下一轮开始前才重启 Agent。
5. 面板重新打开后仍显示最新 Settings 配置。

## 8. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| LangChain 在线流式事件与假测试不同 | 思考球或工具折叠丢事件 | 以真实 benchmark 作为默认切换前置条件 |
| 不同模型供应商 tool calling 表现不一致 | 默认切换后部分兼容端点退化 | 默认切换前至少覆盖当前用户配置的真实 base URL |
| E2E 测试过重 | 本地开发变慢、CI 不稳定 | E2E 单独命令运行，普通 `npm test` 保持快速 |
| 诊断面板过度复杂 | 增加维护成本 | 只展示最近一轮和当前会话汇总，不做图表和远程上报 |
| MCP 边界过早抽象 | 代码膨胀 | 只保留 `Tool` 协议与 fake tool 契约测试，真实 MCP 接入时再扩展 |
| 上传日志清理过头 | 后续 OCR 问题不好排查 | 保留正式诊断事件和 Output Channel 阶段日志 |
| Settings 自动刷新误重启 | 当前回答被中断或配置半更新 | 配置变更只刷新 UI；Agent 运行中延迟到下一轮重启 |

## 9. 本版本改进建议

1. 默认 runtime 切换必须由真实指标驱动，不能只因为 0.1.11 已接入 LangChain 就直接切换。
2. 诊断面板先做“能定位问题”的最小版本，不做完整监控系统。
3. UI E2E 应优先覆盖高风险链路，不追求 100% 页面交互覆盖。
4. 首面板模型配置摘要应从 Settings 单向同步，不再在面板里维护第二份敏感配置表单。
5. MCP 边界保持在 `Tool` 协议层，不提前引入 MCP SDK。

## 10. 下一个版本的优化建议

1. 如果 0.1.12 已默认启用 LangChain，可在 0.1.13 评估是否引入 LangGraph checkpoint，但仍需保持旧 `.sessions` 可迁移。
2. 增加不同模型供应商的兼容性矩阵，例如 OpenAI、DeepSeek、通义、智谱等 OpenAI 兼容端点。
3. 将诊断面板扩展为“可导出诊断报告”，用于用户反馈问题时快速定位。
4. 继续补真实 VS Code 使用场景的回归脚本，减少手工验收成本。

## 11. 后续可扩展的优化建议

1. 真实接入 MCP 工具时，再新增 MCP tool adapter，将 MCP tool schema 适配为当前 `Tool` 协议。
2. 当出现多面试官、评分员、总结员协作需求时，再评估 AutoGen / AgentScope。
3. 引入可选 tracing 后端前，先确保本地诊断面板已经能覆盖大多数排障场景。
4. 后续可把 runtime 指标纳入导出报告，但默认不导出敏感文件内容和完整简历文本。
