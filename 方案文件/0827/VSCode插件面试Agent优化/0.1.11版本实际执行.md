执行日期：2026-08-31

## 1. 框架选择

最终选择 LangChain / LangGraph 作为迁移目标：

1. LangChain `create_agent` 与当前单 Agent + 工具调用循环最接近。
2. LangChain 支持 OpenAI 兼容 `base_url`，能复用当前模型配置。
3. LangChain 事件流可映射到现有 Webview 的 `stream` / `tool_call` 通知。
4. LangGraph 保留为后续状态图和 checkpoint 方向，本版本不直接替换 `.sessions` 落盘格式。

AutoGen 和 AgentScope 未接入正式依赖，继续保留给多 Agent 面试官、评分员、总结员场景。

## 2.1 上传点击补充修复

后续测试发现点击上传简历无反应，定位到上传区依赖 `<label for="resumeFileInput">` 和透明 file input 的默认行为。VS Code Webview 中该默认链路不够稳定，且大文件会进入 Webview `FileReader -> base64 -> Host 临时文件` 链路，容易长时间停留在“正在读取简历...”。

修复：

1. [index.html](../../../vscode-extension/src/webview/index.html) 将上传容器从 `label` 改为普通 `div`，移除 `for="resumeFileInput"`，避免浏览器默认 file input 行为干扰。
2. [main.js](../../../vscode-extension/src/webview/main.js) 将点击和 Enter/Space 键盘上传改为发送 `pickResume`，由 VS Code Host 打开系统文件选择器并直接解析本地文件路径。
3. [styles.css](../../../vscode-extension/src/webview/styles.css) 保留隐藏 input 但禁用鼠标截获，仅作为拖拽 File 对象兜底链路配套。
4. [webview-template.test.ts](../../../vscode-extension/test/webview-template.test.ts) 增加模板断言，确保不再出现 `for="resumeFileInput"` 和 `resumeFileInputEl.click()`，并确认点击会发送 `pickResume`。

## 2.2 上传后一直读取补充修复

继续测试发现点击上传后会长期停在“正在读取简历...”。复查后发现点击上传仍走 Webview `FileReader -> base64 -> Host 临时文件` 链路，大 PDF 或图片会把整份文件内容塞进 Webview 消息，不适合作为点击上传的主路径。

修复：

1. [main.js](../../../vscode-extension/src/webview/main.js) 将点击/键盘上传改为发送 `pickResume`，由 VS Code Host 打开系统文件选择器并直接用本地路径解析。
2. 保留 `FileReader -> pickResumeUpload` 作为系统拖拽 File 对象的兜底路径。
3. [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 增加 `withResumeParseTimeout`，任意解析分支卡住时返回“读取简历超时”，避免 UI 永远停在读取状态。
4. [resumeParser.test.ts](../../../vscode-extension/test/resumeParser.test.ts) 增加解析超时回归测试，并补充“点击上传走 Host 文件选择器并成功回传 `resumePicked`”的闭环测试。

## 2.3 PDF 上传临时调试日志

为继续定位真实 PDF 上传失败原因，增加临时 `[resume-debug]` 调试输出：

1. [main.js](../../../vscode-extension/src/webview/main.js) 在 Webview 控制台输出点击上传、拖拽读取、Host 回传状态、成功和失败事件。
2. [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 在 VS Code Output 的 `Interview Agent` 通道输出文件选择器打开、文件路径、扩展名、大小、PDF 文本提取、OCR 触发、成功、失败和耗时。
3. [webview-template.test.ts](../../../vscode-extension/test/webview-template.test.ts) 增加 `[resume-debug]` 控制台日志断言。

这些日志只打印路径、大小、阶段、耗时和错误，不打印简历正文。PDF 问题定位完成后应清理这部分临时调试输出。

## 2.4 PDF 解析卡住修复

用户上传 `D:\Doc\洪海艳-Java开发.pdf\洪海艳-Java开发.pdf` 后，日志显示文件选择和读取均成功，但停在 `pdf text extraction start`，直到 150 秒总超时。直接用同一 PDF 在本地验证，`pdf-parse` 命令行和 Python / PyMuPDF 都能提取文字，说明问题集中在 VS Code Extension Host 中旧版 `pdf-parse` 的文本提取不稳定。

修复：

1. [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 为 PDF 主文本提取增加 `PDF_TEXT_PARSE_TIMEOUT_MS = 8000`，避免 `pdf-parse` 卡住时等待 150 秒总超时。
2. [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 新增 `runResumePdfText`，通过当前配置的 Python + PyMuPDF 提取 PDF 文字层；这不是 OCR，速度更快，作为 `pdf-parse` 超时或报错后的备用解析。
3. [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 保持原有 OCR 作为最后兜底：`pdf-parse` 失败后先 PyMuPDF，PyMuPDF 仍提取不到文字时再进入 OCR。
4. [resumeParser.test.ts](../../../vscode-extension/test/resumeParser.test.ts) 增加“PDF 主解析器卡住时触发文字层备用解析”的回归测试。

## 3. 取舍

1. 0.1.11 没有删除自研循环，`native` 仍为默认 runtime。
2. LangChain 依赖作为可选能力，不随 VSIX 打包 Python 依赖缓存。
3. 会话落盘仍使用 `.sessions/{id}.json` messages 列表，避免破坏旧会话。
4. LangChain runtime 先适配当前四个内置工具，不提前扩展 MCP / 多 Agent 抽象。
