# Interview Agent 0.1.11 版本开发任务清单

调研日期：2026-08-31

## 1. 本版本结论

0.1.11 选择 **LangChain / LangGraph** 作为 Agent 框架迁移目标。

迁移策略：**受控迁移，不硬切主链路**。

1. 用 LangChain 的 `create_agent` / tool / streaming 能力承接当前单 Agent + 工具调用循环。
2. 用 LangGraph 作为后续状态图、持久化、可观测性和人工介入能力的扩展方向。
3. 0.1.11 先新增 `AgentRuntime` 边界和 `langchain` runtime 实现，保留当前 `native` runtime 作为默认回滚路径。
4. 不选择 AutoGen 作为本版本迁移目标，因为当前还不是多 Agent 团队协作产品。
5. 不选择 AgentScope 作为本版本迁移目标，因为当前优先级是 VS Code 插件内的稳定运行、包体积和现有协议兼容。

参考资料：

1. LangChain 官方文档：[LangChain Python Agents](https://docs.langchain.com/oss/python/langchain/agents)
2. LangChain 官方文档：[LangChain Python Streaming](https://docs.langchain.com/oss/python/langchain/streaming)
3. LangChain 官方文档：[LangChain Models](https://docs.langchain.com/oss/python/langchain/models)
4. LangGraph 官方文档：[LangGraph Workflows and Agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents)
5. 既有评估文档：[0.1.10版本Agent框架评估.md](./0.1.10版本Agent框架评估.md)

## 2. 选择 LangChain / LangGraph 的理由

| 评估项 | 当前项目需求 | LangChain / LangGraph 匹配情况 |
|---|---|---|
| 单 Agent 面试流 | 当前是一个面试官 Agent 持续追问 | `create_agent` 与当前 `AgentLoop.run()` 最接近 |
| OpenAI 兼容模型 | 当前支持 `api_key`、`model`、`base_url` | LangChain 文档支持通过 OpenAI provider 和 `base_url` 接入兼容服务 |
| 工具调用 | 当前工具基于 OpenAI function schema | LangChain 支持 Python tools，需做一次最小 adapter |
| 流式输出 | Webview 依赖 token delta 和工具通知 | LangChain 支持 agent event streaming，可映射到现有 `notify_stream` / `notify_tool_call` |
| 历史与会话 | 当前 `.sessions/{id}.json` 自行落盘 | 0.1.11 先保留现有落盘格式，LangGraph checkpoint 后续再评估 |
| 体积风险 | 0.1.10 已优化 VSIX 体积 | 先做可选 runtime，验证依赖大小后再决定是否默认启用 |

结论：LangChain / LangGraph 是本项目当前阶段成本最低、收益最直接的迁移目标。AutoGen 和 AgentScope 继续保留为后续多 Agent 方向，不进入 0.1.11 正式迁移范围。

## 3. 本版本目标

1. 抽出 `AgentRuntime` 协议，让现有 `AgentLoop` 成为 `native` runtime。
2. 新增 `LangChainAgentRuntime`，复用当前 `LLMClient` 配置、`ToolRegistry` 工具和协议回调。
3. 增加运行时选择配置，默认仍为 `native`，可切换 `langchain`。
4. 保持 VS Code Webview 通知协议、思考球工具折叠展示、会话文件格式不变。
5. 通过同一批单测和集成测试验证两个 runtime 的关键行为一致。
6. 记录迁移收益、依赖体积、冷启动耗时、首 token 耗时和未迁移原因。

暂不做：

1. 不接入 LangSmith、远程 tracing、云端部署或外部控制台。
2. 不把 AutoGen / AgentScope 加入正式依赖。
3. 不把会话落盘直接迁到 LangGraph checkpoint。
4. 不重写工具实现，只做 adapter。
5. 不改变 Webview 消息协议和历史 JSON 格式。

## 4. 当前状态与冲突检查

| 当前逻辑 | 用户期望 | 冲突点 | 处理策略 |
|---|---|---|---|
| [agent_loop.py](../../../agent/agent_loop.py) 自行 while 循环处理 LLM 和工具 | 使用主流 Agent 框架迁移 | 直接替换会影响流式输出、取消、工具通知、历史压缩 | 先抽 runtime 协议，保留 native 回滚路径 |
| [session.py](../../../agent/session.py) 持有 `AgentLoop` 并落盘 `loop.messages` | 新 runtime 也要进入会话管理 | 新 runtime 若自带状态管理，可能破坏旧会话恢复 | 0.1.11 要求 runtime 都暴露 `messages`，继续由 `SessionStore` 保存 |
| [llm_client.py](../../../agent/llm_client.py) 统一 OpenAI 兼容调用与错误分类 | LangChain 也会封装模型调用 | 错误分类、模型连接测试可能被绕过 | 模型连接测试继续走现有 `OpenAIClient.test_connection()`；LangChain 只用于对话 runtime |
| [tools/base.py](../../../agent/tools/base.py) 工具 schema 是 OpenAI function 格式 | LangChain 工具需要 Python callable/schema | schema 转换可能丢参数说明 | 写最小 adapter，并用现有工具单测覆盖参数传递 |
| `stop` 通过 `should_cancel` 轮询中断 | 框架内部调用可能隐藏循环 | 取消响应速度可能变慢 | 只在可控制的 event streaming / 工具执行边界接入；达不到标准则不默认启用 |

## 7. 验收步骤与验收标准

### 7.1 自动化验收

在项目根目录执行：

```powershell
cd D:\project\interview-agent
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check agent
```

在 VS Code 扩展目录执行：

```powershell
cd D:\project\interview-agent\vscode-extension
npm test
npx tsc -p ./ --noEmit
npm run compile
npm run prepare-agent
npm run package
```

自动化验收标准：

1. Python 全量测试和 ruff 通过。
2. VS Code 扩展测试、类型检查、编译、打包通过。
3. 打包产物为 `interview-agent-0.1.11.vsix`。
4. `bundled-agent` 包含新增 runtime 文件。
5. 默认 `native` runtime 下旧测试不退化。

### 7.2 手工验收

1. 安装 0.1.11 VSIX：

   ```powershell
   code --install-extension D:\project\interview-agent\vscode-extension\interview-agent-0.1.11.vsix --force
   ```

2. 执行 `Developer: Reload Window`。
3. 默认配置下打开 `Interview Agent`，发送一轮会触发工具调用的问题，确认仍走 native。
4. 将设置 `interview.agentRuntime` 改为 `langchain`。
5. 重新打开面板或重启插件进程，发送同一轮问题。
6. 确认回答流式输出正常，思考球右侧折叠详情仍能看到工具开始、参数、结果。
7. 点击停止按钮，确认生成或下一次工具执行能被中断。
8. 关闭并重新打开 VS Code，确认历史会话仍可恢复。

手工验收标准：

1. `native` 和 `langchain` 两种 runtime 都能跑通基本面试对话。
2. 工具调用内容仍可折叠查看。
3. 切换 runtime 不破坏模型配置、简历上下文、会话历史和 OCR 上传。
4. 缺少 LangChain 依赖时提示明确，native 仍可使用。

## 8. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| LangChain 事件格式变化 | 流式输出或工具通知映射失败 | adapter 层隔离事件格式，测试只断言项目内部回调 |
| 工具 schema 转换不完整 | 模型调用工具参数错误 | 先覆盖四个内置工具，不做通用 JSON Schema 全量转换器 |
| 取消不如 native 及时 | 用户停止后仍继续生成 | 设定验收标准；不达标则 0.1.11 不默认启用 langchain |
| 依赖体积增加 | 抵消 0.1.10 VSIX 瘦身成果 | 可选依赖 + 打包清单复核，不把 venv 打进 VSIX |
| 历史格式变化 | 老会话无法恢复 | 0.1.11 明确禁止修改 `.sessions` JSON messages 格式 |
| 错误分类变粗 | 用户看不懂模型配置失败原因 | 模型连接测试继续使用现有 `OpenAIClient.test_connection()` |

## 9. 本版本改进建议

1. 0.1.11 的迁移目标应是“可切换 runtime”，不是删除自研循环。
2. LangChain runtime 先覆盖当前四个内置工具，不为未来 MCP / 多 Agent 提前做大抽象。
3. 默认仍使用 native，等真实运行指标稳定后再考虑把 LangChain 设为默认。
4. 执行记录必须写清楚 LangChain 相比 native 的收益和成本，避免为了框架而框架。

## 10. 下一个版本的优化建议

1. 如果 0.1.11 的 LangChain runtime 通过真实验收，0.1.12 可考虑逐步把默认 runtime 改为 `langchain`。
2. 如果工具链继续变复杂，0.1.12 再评估是否用 LangGraph 显式状态图替代 `create_agent` 默认循环。
3. 补端到端 UI 自动化，覆盖 runtime 切换、思考球工具折叠、上传 OCR 和会话恢复。
4. 继续修复系统文件资源管理器拖拽上传，并纳入 VS Code Webview 实测记录。

## 11. 后续可扩展的优化建议

1. 当出现多面试官、评分员、总结员协作需求时，再重新评估 AutoGen / AgentScope。
2. 将 runtime 指标沉淀为诊断面板：模型耗时、工具耗时、token 粗估、错误分类。
3. 在 LangGraph 方向成熟后，再考虑 checkpoint、人工确认节点和更细的面试流程图。
4. 将工具 adapter 设计成 MCP 可复用边界，但只有接入真实 MCP 工具时再扩展。
